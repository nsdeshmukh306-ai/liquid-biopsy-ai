# Reproducing the reported results

Everything below reproduces numbers on `data/feature_matrix.csv`, whose feature origin is unverified (see the end of this file). Rerun on 2026-10-17 (CPU only, torch 2.14.1, scikit-learn 1.7.2, Python 3.10, seed 42).
Raw outputs of that rerun are in `docs/rerun_2026-10-17/`.

## Which script gives which number

| README claim | Script | Reproduced? |
|---|---|---|
| 5-fold CV AUC 0.943 +/- 0.015, BalAcc 0.872 +/- 0.043 (CNN+LSTM, n=300) | `scripts/07_cv5fold.py` | AUC 0.9429 +/- 0.0142, BalAcc 0.8754 +/- 0.0625 (matches to rounding for AUC; BalAcc within 0.003) |
| Hold-out test AUC 0.921, TP=34 FP=1 FN=4 TN=6 (n=45) | the committed `model/best_model.pt` (epoch-5 checkpoint, chosen on validation loss) on `data/processed_real/X_test.npy` | Yes, exactly: AUC 0.9211, AUPRC 0.984, BalAcc 0.876, Sens 34/38, Spec 6/7. Run `python scripts/cross_cohort_validation.py` (prints it before looking for the external cohort). |
| LR / RF CV AUC 0.969 / 0.988 | `scripts/train_baselines.py` | Yes (0.969 +/- 0.015, 0.988 +/- 0.006) |

## Two different neural-net protocols in this repo

- `07_cv5fold.py`: 5-fold on all 300 samples, up to 60 epochs, early stopping per fold. Source of the README headline.
- `03_train_model.py`: 5-fold on the 255 train+val samples, then a final model on all 255 (up to 50 epochs, keeping the lowest-training-loss state), saved to `model/best_model.pt` (overwriting the committed checkpoint). A rerun gave CV AUC 0.923 +/- 0.098 (fold 1 = 0.736). The same run printed hold-out AUC 0.848; `04_evaluate.py` on the file it saved printed 0.906. By reading the code (not tested by experiment), the two scripts score the same weights differently: `03` re-standardises `X_test` with a scaler fit on the already-standardised train+val array, while `04` feeds `X_test` as stored. The committed checkpoint differs from both: it is an epoch-5 checkpoint selected on validation loss, which scored 0.921 on the stored test array (the `04`-style input). Why the weights differ from a fresh `03` run (stopping rule, seed, code version) is not established.
- `train_baselines.py` mixes protocols in one table: LR/RF use 5-fold, CNN-only/LSTM-only use 3 folds, and the CNN+LSTM row is read from `training_summary.json` (script 03).

## Caveats

- The 45-sample hold-out has only 7 healthy samples. Logistic regression gets test AUC 1.0 on it, so it cannot rank models.
- This is not evidence about the Nextflow BAM pipeline, and the matrix's features have unverified origin (see DATA_PROVENANCE.md).
- The cross-cohort (Jiang HCC) validation needs `results/validation/jiang_hcc_features.csv`, which is not in this repo. It has not been run. Its labels must be 1 = cancer, 0 = healthy.
- `README.md` mentions a `results/` folder that is not committed; it is regenerated by running the scripts (`01_preprocess.py` first).

## About the cross-cohort script (not a completed external validation)

- Checking that external labels are 0/1 does not verify that 1 means cancer in that cohort. The mapping must be confirmed from the cohort's metadata by hand.
- Feature alignment is now strict: the script stops if any of the 156 internal feature columns is missing or has missing values (the old version zero-filled and only warned under 50% overlap). Matching column names still does not prove matching definitions (bin edges, `methylation_density`, normalisation). Check these by hand.
- Regression checks run on 2026-10-17: (1) with no external file it prints the internal hold-out metrics and stops; (2) with a throwaway test CSV holding only the fragment bins, it stops with "lacks 6/156 internal feature columns"; (3) with a throwaway CSV with labels {1,2}, it stops with a label error. The throwaway files were synthetic, deleted afterwards, and are not evidence. No external cohort was ever evaluated.
- Provenance: see "Provenance audit" in DATA_PROVENANCE.md. Labels match GEO metadata. The features are untraceable to GEO (its files are methylation calls), the schema file calls them "synthetic fragment features", and the producing script is missing. All numbers on this page are results on that supplied matrix, not evidence of real-world performance.
